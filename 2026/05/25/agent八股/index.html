4.用的Agent框架是什么？ReAct模型还是Plan-and-Execute?

ReAct的精髓在于思考->行动->观察的迭代循环，类似边走边想，而Plan-and-Execute是先生成完整计划再按计划执行。、

ReAct根据每一步的观察结果动态灵活调整下一步，适用于开放式、具有探索性的任务（信息检索、科研探索）

Plan-and-Execute在开始就确定好所有步骤、执行，适用于结构化、流程化任务（如生成报告、数据处理）

5.怎么让模型不瞎编参数、准确调用工具？

一是用模型自带的function calling,它返回的就是结构化数据，直接解析

二是如果模型不支持function calling，就把工具定义写清楚，参数类型、必填项、例子给足、在Prompt里硬性要求输出json，再加一层正则解析和格式校验，不对则重试最多2次，关键参数会在后端设置默认兜底值

6.Agent的记忆怎么搞？长期短期分别怎么存？

(1)短期记忆：是当前对话或任务执行过程中的上下文状态，具有易失性。

(2)长期记忆：跨会话（Session）持久化的知识和事实，类似agent的硬盘

(3)短期记忆转长期记忆机制

大脑（LLM）：负责理解和推理，把你的模糊指令拆解成一步步可执行的计划。

记忆（Memory）：能记住上下文（短期）和你的偏好（长期），比如记住你不喝冰的。

规划（Planning）：遇到复杂任务时，能自己反思和纠错。比如订票失败，会自动尝试刷新或切换备选方案。

工具（Tools）：这是它与普通ChatBot最本质的区别。它能调用外部API、操作软件、操纵鼠标键盘，甚至控制物理机器人。

一个被封装的、可复用的函数接口（Function/API）。它接收明确的输入参数，执行一个确定的、原子性的操作，并返回明确的输出结果。

一个由大语言模型（LLM）驱动、具备环境感知能力的自主计算实体。它通过推理（Reasoning） 将模糊的、长期的目标动态拆解为实时计划，并通过循环迭代（ReAct Loop） 自主选择调用工具或子流程，直至达成目标。

一个预定义的、由有向无环图（DAG）或状态机（State Machine）描述的任务执行序列。它将一系列工具或人工操作按照固定的逻辑规则（顺序、分支、并行、循环）编排起来

我理解 Agent 和 Workflow 最核心的区别是「谁来决定下一步」。Workflow 是我提前把流程写死的，每一步怎么走都是固定的，确定性高、好控制；Agent 是让 LLM 自己决定下一步做什么，灵活但不可控。 常见的设计范式除了纯 Agent 之外，还有 ReAct、Plan-and-Execute、Reflection 这几种。 我在实际工程里用得最多的反而是把两者混用，固定流程的部分用 Workflow，需要灵活决策的节点嵌入 Agent 能力，这样既保住了整体可控，又有局部的灵活性。
