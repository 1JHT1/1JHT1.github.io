HTTP状态码

1️⃣ 信息响应（1xx）—— 临时通知

平时不太常见，但有一个是“八股新宠”：

  • 100 Continue：客户端发了大请求头，服务器回复“你继续发 body 吧”。
  • 101 Switching Protocols：服务器同意切换协议（如从 HTTP 升级到 WebSocket）。

2️⃣ 成功响应（2xx）—— 一切正常

  • 200 OK：最经典。表示请求成功。但对于 DELETE 操作，很多规范建议返回 204 更语义化。
  • 201 Created：创建成功。通常在 POST 提交数据后返回，并建议在响应头中携带 Location 字段指向新资源的 URI。
  • 204 No Content：处理成功，但没数据返回。常见于 DELETE 操作或 PUT 更新操作，告诉前端“我搞定了，但响应体是空的，你别解析”。

3️⃣ 重定向（3xx）—— 搬家了，请绕行

这是面试中的“文字游戏”重灾区：

  • 301 Moved Permanently：永久重定向。浏览器会缓存这个地址，下次直接访问新地址（SEO 会将旧权重转移给新地址）。注意：请求方法可能从 POST 变为 GET。
  • 302 Found：临时重定向（旧标准叫 302 Moved Temporarily）。每次还会访问旧地址，再由服务器指路。注意：早期规范会改变方法（POST 转 GET）。
  • 303 See Other：明确要求改用 GET。常用于 POST 提交表单后重定向到结果页（PRG 模式），防止表单重复提交。
  • 307 Temporary Redirect：临时重定向，但方法不变。如果原来是 POST，重定向时必须还是 POST（替代 302 的语义混乱）。
  • 308 Permanent Redirect：永久重定向，但方法不变（替代 301 的语义混乱）。
  • 304 Not Modified：缓存命中的身份证。客户端有缓存，服务器告诉你“内容没变，直接用你本地的”，不会返回响应体。注意：它不属于重定向，但归类在 3xx。

4️⃣ 客户端错误（4xx）—— 是你（前端/调用方）的问题

  • 400 Bad Request：语义错误或参数格式不对。比如 JSON 格式写错了、必填字段没传。千万别只返回“400”，一定要在响应体里告诉调用方具体哪个字段错了！
  • 401 Unauthorized：未认证。用户没登录，或者没提供 Token。关键：必须携带 WWW-Authenticate 头信息。
  • 403 Forbidden：已认证，但没权限。比如普通用户想访问管理员页面。很多公司会用 403 代替 404 来防止目录枚举。
  • 404 Not Found：资源不存在。可能是 URL 拼错了，也可能是数据库里查无此人。
  • 405 Method Not Allowed：HTTP 方法不对。比如只支持 POST，你却发了 GET。响应头必须带上 Allow: POST 告知客户端。
  • 409 Conflict：冲突。常见于编辑冲突（乐观锁版本号不一致），或者用户名已被占用。
  • 429 Too Many Requests：限流了。请求频率超出限制，通常响应头会带 Retry-After 告诉客户端多久后再试。

5️⃣ 服务端错误（5xx）—— 服务器扛不住了

  • 500 Internal Server Error：服务器内部未知错误。这是最通用的“万金油”报错，通常是代码抛了 NullPointerException 等未捕获异常。
  • 501 Not Implemented：功能未实现。服务器不认识这个请求方法，或该功能还在开发中。
  • 502 Bad Gateway：网关错误。通常发生在 Nginx 反向代理场景，意思是**“网关（Nginx）连不上上游服务器（如 Tomcat）”**，比如上游服务挂了或端口不通。
  • 503 Service Unavailable：服务不可用。服务器超载或正在停机维护。通常运维会配合 Nginx 主动返回此状态码。
  • 504 Gateway Timeout：网关超时。网关（Nginx）连上了上游服务器（Tomcat），但上游处理时间太久，没在规定时间内返回结果。
